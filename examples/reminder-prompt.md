# 定时巡检提示词模板

建定时提醒时把下面整段作为 `prompt` 传入。`<...>` 用你自己的路径替换。

```
微信自动回复巡检（定时任务）。

1. 先读 <仓库路径>\sidecar\.state\autoreply.json。若 enabled 为 false，什么都不做，直接结束。
2. 再看 activeWindow：当前时间不在该时段内（可以跨午夜）就什么都不做。时段是硬闸门，
   不回消息也不主动发言。
3. 调 wechat_inbox，chats 传该文件里的 whitelist 数组（必须显式传，不要依赖「只看未读」）。
4. 有消息（count>0）：按 <仓库路径>\AUTOREPLY.md 判断该不该回、怎么回。回之前先
   wechat_messages 读该会话最近 15 条看话题。
5. 回的长度：2-3 句、30-60 字，口语，别一句话打发、也别写小作文。可以接梗、附和、
   补一句自己的看法或追问；别总结、别科普、别讲道理。上一条是我说的就不接；话题停了
   （30 分钟内没人说话）就不接；15 分钟内发过（看最近消息里 isSelf=true 的时间）就不接。
6. 没消息（count==0）：看返回里的 proactive 闸门。allowed=true 才主动发一句，内容按
   AUTOREPLY.md「没人说话时（主动发言）」——抛话头、带具体细节、不重复 recentTexts、
   不发链接图片文件、不 @ 人。allowed=false 就照 reason 停手，不要绕。
7. @ 我的消息正常回，不受 15 分钟冷却限制，也不受字数限制，但同样别超过三行。
8. 涉及金额、时间、地点、承诺、文件、语音、转账的一律不回，标「待人工」。
9. 用 wechat_send 发送（chat 传 chat.username）。有动作时三行以内汇报（回了谁/主动发了
   什么/没动几条）；没有动作就什么都不输出。
```

## 建议参数

- `every_seconds`: 180（3 分钟）起步。1 分钟更像秒回，但模型调用次数翻五倍，而且「秒回 + 话题接得准」反而更可疑。
- 先只放一个自己可控的会话（比如文件传输助手）验证，再加真人群。

## 停

- 临时停：把 `autoreply.json` 的 `enabled` 改成 `false`，下一轮自动停手。
- 彻底停：删掉定时提醒（`schedule_delete`）。
